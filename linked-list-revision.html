Linked Lists — Revision Sheet

A complete reference covering singly, doubly, and circular node-based structures.

Data Structures Dynamic Memory Pointers

Singly Linked Lists

Core Concept
Definition
A linear data structure consisting of nodes where each node contains a data field and a reference to the next node in the sequence, ending in a null pointer.
Key Points
  • Unidirectional Flow — Traversal is restricted to one direction as nodes only maintain a single link to their successor.
  • Dynamic Allocation — Memory size is allocated or de-allocated at run time, allowing the list to grow or shrink as needed.
  • Non-Contiguous Storage — Unlike arrays, nodes are not stored in contiguous memory locations and are linked via pointers.
Formulas & Rules
Property / InvariantMetric / Rule
Access ComplexityO(n) (random access not supported)
Insertion/Deletion (Beginning)O(1) time complexity
Space ComplexityO(n) where n is the number of elements
Head InvariantMust always point to the first node to maintain access
Termination InvariantThe next pointer of the tail node must be null
Core Operations
OperationAlgorithmic MechanismTime (Best / Avg / Worst)Space
Insertion (Beginning)Create a new node, point its next to current head, update head to new node.O(1) / O(1) / O(1)O(1)
Insertion (End)Traverse to the last node (where next is null) and update that pointer to the new node.O(1) (if tail kept) / O(n) / O(n)O(1)
SearchSequentially compare the key element with each node's data field starting from head.O(1) (at head) / O(n) / O(n)O(1)
ReversalIterate through the list, flipping each node's next pointer to its predecessor.O(n) / O(n) / O(n)O(1)
Use Cases
  • Data Structure Implementation — Used as a base to implement higher-level structures like stacks, queues, and graphs.
  • Dynamic Memory Management — Utilized when total elements are unknown at compile time, avoiding array size limitations.

Doubly Linked Lists

Bidirectional
Definition
A node-based structure where each node contains two pointers — one to the next node and one to the previous node allowing traversal in both directions.
Key Points
  • Each node has three components: data + next pointer + prev pointer.
  • Bidirectional Traversal — Enables forward and backward navigation through the list.
  • Extra Memory — Requires more memory per node compared to singly linked lists due to an additional pointer.
Formulas & Rules
OperationTime Complexity
Insertion (Beginning/End)O(1)
Search (both directions)O(n)
Memory per nodeHigher (extra prev pointer)
Things to Remember
🔑
Initialization Rules: Head's prev is always null; Tail's next is always null.
⚠️
Update Both Pointers: When inserting or deleting, remember to update both next and prev references — forgetting one breaks the chain.

Circular Linked Lists

Continuous Loop
Definition
A variation where the last node points back to the head of the list, forming a continuous loop with no null pointer at the end.
Formulas & Rules
ConversionMechanismTimeSpace
Singly to CircularTraverse to the end of a singly list and update last node's next to point to head.O(n) / O(n) / O(n)O(1)
Use Cases
  • OS Task Scheduling — Used in systems where multiple processes are executed in a continuous round-robin cycle.
  • Continuous Playlists — Allows media players to seamlessly loop back to the first song after the final track.
Contrasts: Regular vs Circular
FeatureRegular Linked ListCircular Linked List
End of ListLast node points to NULLLast node points to Head
Traversal EndStops at NULLNever ends (Infinite loop risk)
Pointer EfficiencyRequires head traversal for end opsO(1) for both ends if last pointer used
Things to Remember
🔑
Last Pointer Advantage: Using a last pointer gives direct access to the end (last) AND the beginning (last->next), allowing O(1) insertion at both.
⚠️
Infinite Loop Risk: Because there is no null terminator, traversal logic must explicitly check if it has returned to the starting node.
