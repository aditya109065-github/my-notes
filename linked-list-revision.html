Singly Linked Lists

Core Concept
Definition
A linear data structure consisting of nodes where each node contains a data field and a reference to the next node in the sequence, ending in a null pointer.
Key Points
  • Unidirectional Flow — Traversal is restricted to one direction as nodes only maintain a single link to their successor.
  • Dynamic Allocation — Memory size is allocated or de-allocated at run time, allowing the list to grow or shrink as needed.
  • Non-Contiguous Storage — Unlike arrays, nodes are not stored in contiguous memory locations and are linked via pointers.
Formulas & Rules
Property / InvariantMetric / Rule
Access ComplexityO(n) (random access not supported)
Insertion/Deletion (Beginning)O(1) time complexity
Space ComplexityO(n) where n is the number of elements
Head InvariantMust always point to the first node to maintain access
Termination InvariantThe next pointer of the tail node must be null
Core Operations
Operation Algorithmic Mechanism Time (Best / Avg / Worst) Space
Insertion (Beginning) Create a new node, point its next to current head, update head to new node. O(1) / O(1) / O(1) O(1)
Insertion (End) Traverse to the last node (where next is null) and update that pointer to the new node. O(1) (if tail kept) / O(n) / O(n) O(1)
Search Sequentially compare the key element with each node's data field starting from head. O(1) (at head) / O(n) / O(n) O(1)
Reversal Iterate through the list, flipping each node's next pointer to its predecessor. O(n) / O(n) / O(n) O(1)
Use Cases
  • Data Structure Implementation — Used as a base to implement higher-level structures like stacks, queues, and graphs.
  • Dynamic Memory Management — Utilized when total elements are unknown at compile time, avoiding array size limitations.
Contrasts: Linked List vs Array
FeatureLinked ListArray
Memory AllocationDynamic (one by one)Static/Fixed (whole block)
Access TypeSequential (O(n))Random (O(1))
Insertion/DeletionEfficient (O(1) at ends)Inefficient (requires shifting)
Cache FriendlinessLow (non-contiguous)High (contiguous memory)
Things to Remember
💡
Cache Unfriendly: Nodes are scattered in memory resulting in poor locality of reference and cache misses during traversal.
🚀
Real-Time Advantage: Allows O(1) insertion/deletion at the beginning without shifting elements, critical for time-sensitive tasks.

Doubly Linked Lists

Bidirectional
Definition
A complex linked list where each node contains data and two pointers: one pointing to the next node and another to the previous node.
Key Points
  • Bidirectional Traversal — Facilitates efficient navigation in both forward and backward directions using next and prev pointers.
  • Pointer Overhead — Each node requires more memory compared to a singly linked list due to the additional pointer.
  • Symmetry Rule — For any node N, if N.next is M, then M.prev must be N to maintain structural integrity.
Formulas & Rules
Property / RuleMetric / Formula
Node Memory Consumption(Data Size) + 2 * (Pointer Size) per node
Deletion EfficiencyO(1) time if the pointer to the target node is known
Head/Tail Boundsprev of head and next of tail must be null
Referential ComplexityInsertion/deletion updates 4 pointers (2 for new node, 1 for each neighbor)
Core Operations
Operation Algorithmic Mechanism Time (Best / Avg / Worst) Space
Deletion Update the next of preceding node and prev of succeeding node to bypass target. O(1) / O(1) / O(1) O(1)
Backward Traversal Start from the tail or any middle node and move toward the head using prev. O(1) / O(n) / O(n) O(1)
Insertion at Tail Link new node's prev to current tail, update tail's next to new node. O(1) / O(1) / O(1) O(1)
Use Cases
  • Navigation Systems — Ideal for browser history (back/forward), music playlists, and undo/redo functionality.
  • Deques (Double-Ended Queues) — Efficiently supports insertion and removal from both ends of the data structure.
Contrasts: Singly vs Doubly
ParameterSingly Linked ListDoubly Linked List
MemoryLower (1 pointer/node)Higher (2 pointers/node)
TraversalForward onlyForward and Backward
DeletionRequires pointer to predecessorO(1) if target pointer is known
Things to Remember
✅
Simplified Deletion: The prev pointer eliminates the need to traverse from the head to find the previous node, achieving O(1) deletion.
⚠️
Major Disadvantages: Consumes more memory per node, and pointer implementation is highly complex, increasing the risk of broken links.

Circular Linked Lists

Closed Loop
Definition
A linked list variation where the last node points back to the first node instead of null, forming a continuous closed loop.
Key Points
  • No Termination — There is no traditional NULL end; traversal continues indefinitely unless a break condition is met.
  • Uniformity — Every node has a successor, making the structure ideal for repetitive or round-robin tasks.
  • Structure Types — Can be implemented as a Circular Singly Linked List or a Circular Doubly Linked List.
Formulas & Rules
Property / StateMetric / Rule
Optimization via LastMaintaining a last pointer makes start/end insertion O(1)
Full Cycle TraversalRequires exactly n steps to return to the starting point
Loop InvariantFollowing next links n times always returns to the start
Empty List StateList pointer is null; a single-node list points to itself
Core Operations
Operation Algorithmic Mechanism Time (Best / Avg / Worst) Space
Insertion (Start/End) Link new node to last.next and update pointers to maintain the loop. O(1) / O(1) / O(1) O(1)
Traversal Iterate from a starting node and stop when current node equals the start again. O(n) / O(n) / O(n) O(1)
Singly to Circular Traverse to the end of a singly list and update last node's next to point to head. O(n) / O(n) / O(n) O(1)
Use Cases
  • OS Task Scheduling — Used in systems where multiple processes are executed in a continuous round-robin cycle.
  • Continuous Playlists — Allows media players to seamlessly loop back to the first song after the final track.
Contrasts: Regular vs Circular
FeatureRegular Linked ListCircular Linked List
End of ListLast node points to NULLLast node points to Head
Traversal EndStops at NULLNever ends (Infinite loop risk)
Pointer EfficiencyRequires head traversal for end opsO(1) for both ends if last pointer used
Things to Remember
🔑
Last Pointer Advantage: Using a last pointer gives direct access to the end (last) AND the beginning (last->next), allowing O(1) insertion at both.
⚠️
Infinite Loop Risk: Because there is no null terminator, traversal logic must explicitly check if it has returned to the starting node.
