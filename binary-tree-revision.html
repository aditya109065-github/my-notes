Binary Tree — General Concepts

Foundations
Definition
A non-linear data structure where each node can have a maximum of two children, known as the left and right child.
Key Points
  • Specialised version of a General Tree — each node has at most two children.
  • Each node holds: a data item, address of left child, address of right child.
  • Creates a hierarchical structure similar to an org chart — root at top, branches below.
Formulas & Rules
PropertyFormula
Maximum nodes at level i2^i
Maximum nodes for height h2^(h+1) − 1
Minimum nodes for height hh + 1
Use Cases

Used in binary search trees for efficient searching and in heaps for priority queues and sorting. Real-world applications include virtual memory management and 3D rendering for faster object access.

Things to Remember
⚠️ Without balancing, a binary tree can perform as poorly as a linked list. Worst-case time complexity for search, insert, and delete is O(n).

Binary Tree Terminologies

Vocabulary
Definition
The specific vocabulary used to describe the components and measurements of a tree's structure.
Key Points
  • Root — Topmost node; a tree has exactly one root.
  • Leaf Node — Bottom node with no children.
  • Internal Node — Any node with at least one child.
  • Parent / Child — A preceding node is a parent; its successor is a child.
Formulas & Rules
PropertyFormula
Height of a treeEdges from deepest node → root
Depth of a nodeEdges from that node → root

Full Binary Tree

Proper Binary Tree
Definition
A binary tree where every node has either zero or two children nodes.
Key Points
  • Strictly forbids any node from having exactly one child.
  • Internal nodes always have two children; leaf nodes have zero.
Formulas & Rules
PropertyFormula (given n total nodes)
Number of internal nodes(n − 1) / 2
Number of leaf nodes(n + 1) / 2
Things to Remember
⚠️ Do not assume all leaves must be on the same level — they can appear at any level as long as the 0-or-2 child rule is met.

Complete Binary Tree

Compact
Definition
A tree where all levels are fully filled except possibly the last, which must be filled from left to right.
Key Points
  • Nodes are arranged without missing any sequence in the structure.
  • On the last level, all nodes must be packed as far to the left as possible — no gaps.
Formulas & Rules
PropertyFormula
Minimum nodes for height h2^h
Things to Remember
⚠️ The "left-to-right" rule is critical — even a single gap between nodes on the last level makes the tree not complete.

Perfect Binary Tree

Symmetric
Definition
A symmetrical tree where every internal node has exactly two children and all leaf nodes are on the same level.
Key Points
  • Perfectly balanced — zero empty spaces anywhere.
  • Always both a full and a complete binary tree by default.
Formulas & Rules
PropertyFormula
Height given n nodeslog₂(n + 1)
Things to Remember
💡 The total sum of all levels is always exactly one node less than what the next hypothetical level would hold.

Degenerate (Skewed) Binary Tree

Worst Case
Definition
A tree where each node has only one child node, causing it to grow in a single straight line.
Key Points
  • Left-skewed — All nodes lean toward the left.
  • Right-skewed — All nodes lean toward the right.
  • Behaves identically to a linked list in terms of performance.
Formulas & Rules
OperationTime Complexity
Search / Insert / DeleteO(n)
Things to Remember
⚠️ This is the worst-case scenario for binary tree efficiency — it loses all benefits of hierarchical storage.

Balanced Binary Tree

Self-Balancing
Definition
A tree where the height of the left and right subtrees of any node differ by no more than one.
Key Points
  • For a tree to be balanced, its left and right subtrees must also be balanced.
  • Maintains efficient performance by preventing the tree from becoming skewed.
Things to Remember
⚠️ A difference of 2 or more in subtree heights violates the balanced condition.

B+ Tree

Database / Disk
Definition
An advanced balanced search tree where all actual data is stored only in leaf nodes, while internal nodes store only keys for navigation.
Key Points
  • All leaf nodes are linked in a single linked list for efficient range-based queries.
  • High "fan-out" — many children per node keeps tree height short.
  • Designed to be disk-efficient and cache-friendly for database systems.
Formulas & Rules
Property / OperationFormula / Complexity
Search / Insert / DeleteO(log n)
Min children (non-root internal node)⌈m/2⌉
Min keys (non-root internal node)⌈(m−1)/2⌉
Root node childrenMinimum 2
Use Cases

Widely used in database indexing and file systems where fast retrieval of sorted data from disks is required. Preferred for range-based queries due to linked leaf nodes.

Things to Remember
⚠️ Major difference from B-Trees: B+ Trees store data only in leaf nodes, whereas B-Trees store data in both internal and leaf nodes.

B+ Tree Components

Internal vs. Leaf Nodes
Definition
The specialised node types that serve different roles within the B+ tree hierarchy.
Key Points
  • Internal Nodes — Act as "navigators": store only search keys and tree pointers to lower levels.
  • Leaf Nodes — Act as "data storage": contain actual record keys, data pointers, and a P_next pointer to the next leaf.
  • All leaf nodes must be at the same level.
Formulas & Rules
RuleFormula
Internal node key count (given c pointers)c − 1 keys
Sorted orderBoth node types always keep keys sorted
Things to Remember
💡 Leaf nodes use a P_next pointer to connect to each other — this pointer is not present in internal nodes.
